# MOMO 시연 영상 시나리오 (1차 예선 제출용)

- **목표 길이:** 3분 30초 안팎. 공모전 요강에는 길이 제한이 없고, 목업·프로토타입·화면 녹화를 모두 인정합니다.
- **보여 줄 것:** 심사 기준(차량특화성, 창의성, Pleos SDK 활용)에 맞춰 ① 내비 남은 시간에 맞춰 끝나는 이야기, ② 좌석·벨트로 정하는 역할, ③ 음성 대화, ④ 주행/정차 화면 전환, ⑤ 말로 봇 만들기와 마켓을 차례로 보여 줍니다.
- **등장 가족:** 운전석 엄마, 조수석 아빠, 뒷좌석 지우·지호(앱에 기본으로 들어 있는 이름입니다).

## 촬영 전 준비

1. 에뮬레이터를 켜고 release APK를 설치합니다. 마이크 권한은 이미 허용해 두었습니다.
   ```bash
   adb install -r apk/econovation_MOMO_release.apk
   ```
2. 에뮬레이터는 노트북 마이크로 주변 소리를 그대로 알아듣습니다. 촬영 중에는 macOS 입력 음량을 0으로 낮추고, 아이 발화는 아래 adb 명령으로 넣습니다. 녹음해 둔 아이 목소리를 영상 편집 때 입히면 실제로 말한 것처럼 보입니다.
   ```bash
   adb shell "am broadcast -a app.momo.SAY --es text '용이 피자 먹었으면 좋겠어!' -p app.momo"
   ```
3. 캐릭터 목소리(TTS)가 영상의 핵심이므로 화면과 시스템 소리를 함께 녹화합니다(OBS 등). `adb shell screenrecord`는 소리를 담지 못하고 3분에서 끊깁니다.
4. 이야기는 대본 폴백으로 진행되고, 주행 화면 상태 줄 끝에 '대본'이 표시됩니다. 에뮬레이터에서 Pleos LLM이 응답하지 않기 때문입니다. 자막으로 "에뮬레이터에서는 대본 폴백으로 동작, 실차에서는 Pleos LLM이 응답"이라고 밝혀 두면 심사에서 오해를 피할 수 있습니다.
5. 앱 상태는 메모리에만 남으므로, 다시 찍을 때는 앱을 완전히 종료하고 처음부터 시작합니다.
   ```bash
   adb shell am force-stop app.momo
   ```

## 주의할 점

- 주행 중에는 홈·마켓·만들기 화면이 막힙니다. 8번 장면 전에 반드시 정차 상태인지 확인합니다(도착하면 자동으로 정차됩니다).
- 발화는 캐릭터가 말을 마친 뒤에 넣습니다. 말하는 도중에 넣어도 동작하지만, 영상에서는 차례가 바뀌는 흐름이 잘 보이지 않습니다.
- 5번 장면이 길어지면 시연 패널의 배속 10x로 남은 시간이 줄어드는 모습을 짧게 보여 줄 수 있습니다.
- 시연 패널이 화면을 가리는 구간은 편집에서 잘라 내거나, 패널을 연 다음 바로 '닫기'를 누릅니다.
